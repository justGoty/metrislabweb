# Аналитика МэтрисЛаб

Счётчик Яндекс Метрики: **112569603**. Домен: `metrislab.ru`.
Код загружается только на рабочем домене после отдельного согласия посетителя.
На localhost и без JavaScript запросов к Метрике нет.

## События

В кабинете созданы четыре цели типа «Целевое событие» с точным совпадением идентификатора:

| Идентификатор | Название | ID цели |
| --- | --- | --- |
| `lead_submit_success` | Заявка успешно отправлена | 613033751 |
| `contact_phone_click` | Клик по телефону | 613034542 |
| `contact_email_click` | Клик по электронной почте | 613034730 |
| `lead_form_start` | Начало заполнения заявки | 613035287 |

Главное событие: `lead_submit_success`. Оно отправляется только после успешного HTTP-ответа обработчика с `ok: true`. Это подтверждает приём заявки сайтом, но не доставку письма и не продажу. Клик по телефону не является состоявшимся звонком; клик по почте не подтверждает отправку письма.

## Согласие и данные

- Выбор «Разрешить аналитику» / «Без аналитики» хранится в `localStorage`, ключ `metrislab.analytics.v1`, до 180 дней. Если хранилище недоступно, выбор действует до перезагрузки страницы.
- Изменение выбора доступно в подвале. Отказ останавливает счётчик через `destruct`, очищает доступные сайту записи `_ym*` и отменяет ожидающие события. Выбор синхронизируется между вкладками.
- Согласие на обработку заявки не включает согласие на аналитику. Отказ и блокировщик аналитики не мешают заявке.
- Вебвизор, карты кликов, автоматические цели, электронная коммерция и Тег Менеджер отключены. В коде явно отключены запись заголовка и автоматическое отслеживание ссылок.
- В цели отправляются только фиксированные идентификаторы. Поля формы, файлы, текст ошибок и пользовательские параметры не передаются.
- Из URL удаляются произвольные параметры, `model`, `utm_term` и якорь. Неизвестные пути заменяются на `/404.html`. Реферер сокращается до домена.
- Сохраняются ограниченные по формату `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `yclid`. Для кампаний используйте `utm_source=yandex&utm_medium=cpc&utm_campaign=metris_search_{campaign_id}&utm_content=ad_{ad_id}_group_{gbid}`.
- Метрика всё равно получает технические данные браузера, IP и идентификаторы cookies после согласия. Техническая реализация не заменяет юридическую проверку политики.

## Файлы

- `src/lib/analytics.ts`: загрузка SDK, согласие, очистка URL, фиксированные цели.
- `src/components/AnalyticsConsent.tsx`: панель выбора и кнопка настроек.
- `src/components/ContactForm.tsx`: начало заполнения и подтверждённая отправка.
- `src/pages/PrivacyPage.tsx`: описание аналитики и обработки данных.

## Проверки

```bash
npm run build
npm run lint
npm run test:static
npm run test:analytics
npm run preview -- --host 127.0.0.1 --port 4173
```

Через `playwright-cli run-code --filename ...`:

- `scripts/browser-checks.js`: 16 сочетаний страниц и экранов, каталог, форма, язык, мобильное меню, отсутствие JS.
- `scripts/analytics-browser-checks.js`: SDK и обработчик формы подменены. Проверяет четыре цели, отказ, отзыв, просроченное согласие, закрытое хранилище, синхронизацию вкладок, позднюю загрузку SDK, ошибки API и отсутствие данных формы в событиях.
- `scripts/analytics-sdk-checks.js`: загружает настоящий SDK Яндекса, но перехватывает всю телеметрию. Проверяет фактический формат просмотра и цели, очистку URL. Успешный результат содержит `passed: true`; тестовые события не отправляются в Метрику.
- `scripts/production-browser-checks.js`: чтение опубликованного сайта с отказом от аналитики, без отправки формы.

Контрольная реальная заявка требует отдельного согласования. Отчёт Метрики не покажет всех посетителей: отказ, блокировщики и ограничения браузера уменьшают охват.
